Developers

Move money with three lines of code.

A REST API designed by engineers who were tired of banking APIs: predictable objects, idempotent writes, signed webhooks and a sandbox that tells the truth.

Create a transfer

POST /v1/transfers
curl https://api.vaultline.example/v1/transfers \
  -H "Authorization: Bearer $VAULTLINE_KEY" \
  -H "Idempotency-Key: inv-2291" \
  -d amount=8400000 \
  -d currency=usd \
  -d to=acct_halcyon \
  -d memo="INV-2291"
import { Vaultline } from "@vaultline/node";

const vaultline = new Vaultline(process.env.VAULTLINE_KEY);

const transfer = await vaultline.transfers.create(
  { amount: 84_000_00, currency: "usd", to: "acct_halcyon", memo: "INV-2291" },
  { idempotencyKey: "inv-2291" },
);

console.log(transfer.status); // "pending" → "settled"
import os
from vaultline import Vaultline

vaultline = Vaultline(os.environ["VAULTLINE_KEY"])

transfer = vaultline.transfers.create(
    amount=84_000_00,
    currency="usd",
    to="acct_halcyon",
    memo="INV-2291",
    idempotency_key="inv-2291",
)

print(transfer.status)  # "pending" -> "settled"

Built for production from the first request

  • 01

    Idempotent writes

    Every POST accepts an Idempotency-Key. Retries never move money twice.

  • 02

    Signed webhooks

    HMAC-SHA256 signatures, exponential retries and a replay endpoint.

  • 03

    Typed SDKs

    Node, Python and Go — generated from one OpenAPI spec, versioned together.

  • 04

    Honest sandbox

    Simulate wires, card declines, returns and outages on demand.

  • 05

    Scoped API keys

    Restrict keys by resource, action and IP range; rotate without downtime.

  • 06

    Versioned by date

    Pin a version per key. Breaking changes never arrive unannounced.
